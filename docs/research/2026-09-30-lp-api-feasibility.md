A swap route using this pool does not prove the LP API works for this pool.

The current [Uniswap LP integration guide](https://developers.uniswap.org/docs/liquidity/liquidity-provisioning-api/integration-guide) describes `/lp/check_approval`, `/lp/create`, `/lp/increase`, `/lp/decrease`, `/lp/claim_fees` and `/lp/pool_info`. It says approval and transaction validation remain the integrator's responsibility, with the user's wallet signing and broadcasting. Its v3 decrease flow may include fee collection; UI must avoid counting those fees twice. The [pool-info API](https://developers.uniswap.org/docs/api-reference/pool_info) accepts a v3 token pair, fee and chain ID and returns pool identity, tick and liquidity fields. The separate [v3 position-fetching guide](https://developers.uniswap.org/docs/sdks/v3/guides/managing-liquidity/position-fetching) documents owner NFT IDs and `positions(tokenId)` reads; it is not itself an indexed portfolio service.

`node scripts/smoke-lp-pool-info.mjs` makes exactly one authenticated, **read-only** request for Polygon 137, native USDC/WETH and fee 500. It validates the returned pool address, token addresses/decimals, protocol and live-state field shapes. It reads `UNISWAP_LP_API_KEY` if set, otherwise `UNISWAP_API_KEY`, from ignored `apps/api/.env`. The agent's restricted network returned `{"errorKind":"NETWORK"}`, but the owner's host returned `{"status":200,"poolCount":1,"poolMatches":false,"stateShapeValid":false,"activeLiquidityPositive":false}` twice. HTTP 200 establishes endpoint/key access for this read; the false flags **do not** establish which field differs or whether the candidate pool is wrong. The `stateShapeValid` and liquidity flags remain false whenever identity fails, so they are not separate evidence of empty liquidity.

The bounded `poolChecks` output identified: Polygon chain, v3 protocol, expected pool address, native-USDC/WETH pair, fee and state field shapes matched; `tokenDecimalsMatch` was false with `tokenDecimalsTypes:["string","string"]`. The corrected probe checks exact expected decimal values as numbers or canonical strings, preserving rejection of wrong values, reversed token-decimal mappings and noncanonical strings such as `"06"`. It prints `poolChecks` **only on mismatch** and never prints the API key, wallet, request ID, arbitrary upstream strings, raw response or transaction data. The owner's next read-only run passed all three Booleans. This does not independently prove Polygon state. Uniswap's [pool-info API reference](https://developers.uniswap.org/docs/api-reference/pool_info) documents the requested token pair, fee, chain and response fields used by this probe.

`node scripts/smoke-lp-onchain.mjs` is the next independent, read-only cross-check. It uses the configured Polygon RPC to pin one recent block, read the canonical v3 factory's `getPool` and fee tick spacing, read the pool's factory/token/fee/tick/active liquidity/`slot0` values and both token decimals at that same block, then re-read the block hash. It reports only safe public block metadata and comparison booleans. A matching LP API response and a matching on-chain read still do not verify unsigned LP action payloads or position economics. The checks follow Uniswap's [v3 pool immutables](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolImmutables.sol), [pool state](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolState.sol), and [factory](https://github.com/Uniswap/v3-core/blob/main/contracts/UniswapV3Factory.sol).

The agent's sandbox attempt returned `{"errorKind":"RPC_UNAVAILABLE","stage":"chain"}` because it cannot reach the owner's configured RPC from this environment. The host run is required. A real RPC failure reports only a bounded stage (`chain`, `block`, `factory`, `pool`, `tokens`, `confirmation`, or `validation`), never a provider error body or credential-bearing URL.

Even a matching `/lp/pool_info` result is only the first LP gate. Before enabling a position UI or wallet controls, verify access and exact unsigned response shapes for approval, create, increase, decrease and claim on Polygon; validate the manager/spender/calldata/recipient/amount bounds independently; define position discovery and fee freshness; then test on a wallet/fork. Do not infer USD TVL or APR from the returned `poolLiquidity` field.
