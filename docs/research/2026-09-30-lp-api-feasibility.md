# Polygon LP API feasibility — read-only gate

**Status:** API shape researched; live Polygon result not yet observed. No LP write code or wallet action is approved by this note.

The candidate is the native-USDC/WETH Uniswap v3 0.05% pool `0xA4D8c89f0c20efbe54cBa9e7e7a7E509056228D9`, identified in the earlier [pool research](2026-09-27-polygon-weth-usdc.md). Uniswap's [Polygon v3 deployment list](https://developers.uniswap.org/docs/protocols/v3/deployments/v3-polygon-deployments) identifies the `NonfungiblePositionManager` as `0xC36442b4a4522E871399CD717aBDD847Ab11FE88`. A swap route using this pool does not prove the LP API works for this pool.

The current [Uniswap LP integration guide](https://developers.uniswap.org/docs/liquidity/liquidity-provisioning-api/integration-guide) describes `/lp/check_approval`, `/lp/create`, `/lp/increase`, `/lp/decrease`, `/lp/claim_fees` and `/lp/pool_info`. It says approval and transaction validation remain the integrator's responsibility, with the user's wallet signing and broadcasting. Its v3 decrease flow may include fee collection; UI must avoid counting those fees twice. The [pool-info API](https://developers.uniswap.org/docs/api-reference/pool_info) accepts a v3 token pair, fee and chain ID and returns pool identity, tick and liquidity fields. The separate [v3 position-fetching guide](https://developers.uniswap.org/docs/sdks/v3/guides/managing-liquidity/position-fetching) documents owner NFT IDs and `positions(tokenId)` reads; it is not itself an indexed portfolio service.

`node scripts/smoke-lp-pool-info.mjs` makes exactly one authenticated, **read-only** request for Polygon 137, native USDC/WETH and fee 500. It validates the returned pool address, token addresses/decimals, protocol and live-state field shapes. It prints only HTTP status, count and Boolean checks; no key, wallet address, request ID, raw response or transaction data. It reads `UNISWAP_LP_API_KEY` if set, otherwise `UNISWAP_API_KEY`, from ignored `apps/api/.env`. The agent's restricted network returned `{"errorKind":"NETWORK"}`; this says nothing about the key or API's Polygon support. A host run is needed.

Even a matching `/lp/pool_info` result is only the first LP gate. Before enabling a position UI or wallet controls, verify access and exact unsigned response shapes for approval, create, increase, decrease and claim on Polygon; validate the manager/spender/calldata/recipient/amount bounds independently; define position discovery and fee freshness; then test on a wallet/fork. Do not infer USD TVL or APR from the returned `poolLiquidity` field.

The proposed read and write contracts, including a compact threat model and the launchpad UI reference for later work, are in the [Polygon v3 LP design](../specs/2026-09-30-polygon-v3-lp-design.md).
