# MetaMask EIP-7702 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Independent protocol/evidence exploration uses superpowers:dispatching-parallel-agents. Review the whole branch independently at integration.

**Goal:** Qualify the actual MetaMask single-action wrapper, permit pinned delegated wallets, and recover historical approvals without inventing original contexts.

**Architecture:** Shared strict profile decoder and wallet classifier; API pinned runtime/execution-state proof plus outer-envelope validation; existing swap/LP economics remain authoritative. Preserve direct legacy/type-2 and separate historical reconciliation from original-context receipts.

**Tech Stack:** TypeScript, viem 2.47.18, Zod, Vitest, Next.js, Anvil, local solc 0.8.23.

**Spec:** [design](../specs/2026-10-03-metamask-eip7702-design.md).

## Global constraints

- Base Sepolia 84532 and the four exact MetaMask v1.3.0 addresses in the spec; one zero-value reviewed operation.
- No unknown enforcers, extra calls, TRY mode, general account abstraction or public agent broadcasts.
- Existing amount, deadline, two-confirmation, context and reorg bounds apply.
- Owner `apps/web/next-env.d.ts` and running services must be preserved; isolated build/browser/fork only.
- Existing autonomous execution authorization applies; document choices and concrete blockers.

## Review focus

1. Signature proves delegation only if caveats constrain exact execution; ANY alone is rejected.
2. EIP-7702 authorization can be skipped; end-of-block code alone is insufficient.
3. Outer fees/nonce differ from the reviewed direct action and cannot be silently equated.
4. Old lost contexts need historical evidence, never client-restored trusted issuance.
5. Archived/unverified records must survive resolution; no automatic unblocking or resending.
