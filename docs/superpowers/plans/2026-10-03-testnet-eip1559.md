# Testnet EIP-1559 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Independent web/contracts and harness work may use superpowers:dispatching-parallel-agents with explicit ownership.

**Goal:** Qualify direct EIP-1559 swap/LP wallet execution while preserving legacy recovery.

**Architecture:** Extend the existing reviewed DTO with strict coupled fee fields; use shared core validation/RPC translation and API fee planning/receipt helpers. No deployed contract changes.

**Tech Stack:** TypeScript, Zod, viem, Vitest, Next.js, Anvil.

**Spec:** [design](../specs/2026-10-03-testnet-eip1559-design.md).

## Global constraints

- Base Sepolia 84532; existing router/manager, amounts, TTLs and gas bounds.
- `gasPrice` remains DTO budget ceiling; EIP-1559 requires model/max/priority together and max equals ceiling.
- Legacy recovery remains readable. EIP-7702/relayer unsupported; no recovery erasure, unblocking archive or automatic broadcast.
- Preserve owner `apps/web/next-env.d.ts`; no secrets, public signatures or main Vezta integration.

## Review focus

1. Wallet converts requests to EIP-7702: keep original recovery and report unsupported.
2. Missing/conflicting fee fields: reject at every trust boundary.
3. Base-fee changes after review: preserve envelope and reject insufficient caps.
4. Legacy records survive reload unchanged; new type-2 recovery remains bound.
5. Receipt succeeds with different effective price: verify canonical block math and event economics, not cap equality.
